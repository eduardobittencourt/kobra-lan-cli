# Hardware and Platform Compatibility Matrix

This matrix is the maintained reference for what `kobra-lan` supports, what is verified offline, and what has been observed on live hardware. Runtime qualification rules and `hardware_*_validated` predicates are enforced from a single authoritative registry in `kobra_lan/qualification.py`.

## Evidence tiers

Each row separates three distinct levels of evidence so offline coverage is never confused with live hardware validation:

- **Implemented**: Command, parser, wire format, and safety checks exist in the CLI.
- **Offline-validated**: Covered by the offline `unittest` suite with synthetic transports/fixtures, or by disposable package acceptance probes without touching a printer.
- **Hardware-observed**: Verified directly against a live printer on a local network. Hardware observation never generalizes to unobserved models, firmware versions, slots, materials, preparation flags, or topologies.

## Printer models and firmware

| Model | Model ID (`modelId` / `modeId`) | Firmware | Implemented | Offline-validated | Hardware-observed | Enforcement |
| --- | --- | --- | --- | --- | --- | --- |
| Anycubic Kobra X (`Anycubic Kobra X`) | `20030` | `2.0.2.2` | Yes | Yes | Yes | Qualified; accepted across all commands |
| Anycubic Kobra X (`Anycubic Kobra X`) | `20030` | Any other version | No | Yes (rejection tests) | No | Rejected with exit `2` (`outside_qualification` / validation failure) |
| Other Anycubic models (for example Kobra 3, Kobra S1) | Any other ID | Any | No | Yes (rejection tests) | No | Rejected with exit `2`; never inferred from similar fields |

Missing required `model`, `version`, or `state` fields in fresh MQTT `info` reports fail `doctor` with `qualification_incomplete` (exit `2`); contradictory or unqualified values fail with `outside_qualification` (exit `2`). Optional `deviceId`, `modelId`, and `modeId` fields may be omitted by firmware, but any supplied value must match the saved configuration.

## Slicers and G-code profiles

| Input | Requirement | Implemented | Offline-validated | Hardware-observed | Notes |
| --- | --- | --- | --- | --- | --- |
| Anycubic Slicer Next plain `.gcode` (`<= 128 MiB`) | `; generated by AnycubicSlicerNext <version>` and `; printer_model = Anycubic Kobra X` | Yes | Yes | Yes (Linux `2.0.0.3`, `2.0.0.5`, `2.0.0.6`) | Uploaded byte-for-byte without modification |
| Single-filament `; paint_info` (`paint_index: 0`, tools `<= {0}`) | Valid JSON array, ASCII material, RGB/RGBA color | Yes | Yes | Yes | `hardware_start_validated: true` only for observed onboard slots `1`, `2`, or `4` with `PLA High Speed` below |
| 4-color contiguous `; paint_info` (`paint_index: 0..3`, tools `{0, 1, 2, 3}`) | Matching `T<n>` tool indices, consistent repeated lines | Yes | Yes | Yes (`2026-11-24`, `0=1, 1=2, 2=3, 3=4`) | `hardware_start_validated: true` only for the observed 1:1 PLA High Speed combination below |
| Other multicolor or non-zero/sparse `; paint_info` (subsets, cross-remapped, shared slots) | Matching `T<n>` tool indices, consistent repeated lines | Yes | Yes | No | `print plan`/`print start` report `hardware_start_validated: false` |
| Other slicers (OrcaSlicer, PrusaSlicer, Bambu Studio) or `.3mf` | N/A | No | Yes (rejection tests) | No | Rejected with exit `2` |

## Filament-box topologies and onboard slots

| Topology / slot | Wire identity | Implemented | Offline-validated | Hardware-observed | Notes |
| --- | --- | --- | --- | --- | --- |
| Onboard 4-slot box (`slots list`) | Single box `id: -1`, `ams_index: 0..3` (slots `1..4`) | Yes | Yes | Yes (slots `1..4`) | Read-only inventory works while idle or printing |
| Onboard slots `1`, `2`, `4` (`print start`) | `ams_index` `0`, `1`, `3` | Yes | Yes | Yes | `hardware_start_validated: true` only for observed single-filament and 4-color combinations below |
| Onboard slot `3` (`print start`) | `ams_index: 2` | Yes | Yes | Partial (`2026-11-24`, `2=3` in 4-color 1:1) | Hardware-observed as `2=3` in 4-color `0..3 -> 1..4`; single-filament `0 -> 3` remains unobserved (`hardware_start_validated: false`) |
| External ACE / ACE Pro units | `id != -1` or multiple boxes | No | Yes (rejection tests) | No | Rejected with exit `2` |

## Materials and print preparation combinations

| Combination | `paint_index` / mapping | Preparation flags | Implemented | Offline-validated | Hardware-observed | `hardware_start_validated` |
| --- | --- | --- | --- | --- | --- | --- |
| `PLA High Speed` on onboard slots `1`, `2`, or `4` | Single-filament `0 -> 1\|2\|4` | `auto-leveling: on`, `vibration-compensation: off`, `flow-calibration: off` | Yes | Yes | Yes (2026-10-07, 2026-11-23) | `true` |
| `PLA High Speed` across onboard slots `1..4` (4-color contiguous 1:1) | Multicolor `0 -> 1, 1 -> 2, 2 -> 3, 3 -> 4` | `auto-leveling: on`, `vibration-compensation: off`, `flow-calibration: off` | Yes | Yes | Yes (2026-11-24) | `true` |
| `PLA High Speed` on onboard slot `3` (single-filament) | Single-filament `0 -> 3` | Any | Yes | Yes | No | `false` |
| Other loaded slot materials (for example `PLA`, `PETG`, `TPU`, `ABS`) | Single-filament or multicolor (material family must match G-code) | Any | Yes | Yes | No | `false` |
| Other preparation flag combinations | Any | `auto-leveling: off`, `vibration-compensation: on`, or `flow-calibration: on` | Yes | Yes | No | `false` |
| Other multicolor or non-zero `paint_index` (2/3-color subsets, cross-remapped `paint_index != ams_index`, sparse indices, or shared physical slots) | Any other mapping | Any | Yes | Yes | No | `false` |

## CLI operations

| Command | Mutates printer / local state | Implemented | Offline-validated | Hardware-observed | Runtime qualification flags / notes |
| --- | --- | --- | --- | --- | --- |
| `printer pair` | Writes private profile/PEMs after explicit trust | Yes | Yes | Yes | Requires `--name`, bare IPv4 `--host`, explicit TLS pin consent, and qualified status |
| `printer list\|info\|use\|remove` | Local registry only (`remove` deletes local files only) | Yes | Yes | N/A (offline) | Never contacts the printer or revokes device credentials |
| `doctor` | Read-only | Yes | Yes | Yes | 8 ordered checks; discloses omitted optional MQTT identity fields |
| `status` | Read-only | Yes | Yes | Yes | HTTP `/info` identity plus pinned MQTT `info` report |
| `slots list` | Read-only | Yes | Yes | Yes | Onboard 4-slot box (`id: -1`), idle or printing |
| `camera status` | Read-only | Yes | Yes | Yes (2026-11-25, 2026-11-26 cold-start) | `experimental: true`, `hardware_camera_validated: true` on `20030` / `2.0.2.2`; pinned MQTT `info` + `peripherie` only, never opens port `18088` or exposes stream tokens |
| `camera snapshot` | Read-only-first; optional single-shot `video/startCapture` + `stopCapture` fallback | Yes | Yes | Yes (2026-11-25, 2026-11-26 cold-start, JPEG/PNG 1280×720) | `experimental: true`, `hardware_camera_validated: true` on `20030` / `2.0.2.2`; requires optional external `ffmpeg` on `PATH` (piped via `stdin`, never URL in argv); `--no-start-capture` disables fallback |
| `camera pipe` | Read-only-first; optional single-shot `video/startCapture` + `stopCapture` fallback | Yes | Yes | Yes (2026-11-25, 2026-11-26 cold-start) | Raw HTTP-FLV binary stdout with zero external video dependencies; rejects `--json` (exit `2`); exits `0` on broken pipe and `130` on interrupt; direct cold-boot FLV delivery and `startCapture`/`stopCapture` transitions verified on live firmware |
| `gcode inspect` | Local read-only | Yes | Yes | N/A (offline) | Computes SHA-256/MD5, layers, `paint_info`, tools, and weights offline |
| `files list` / `files info` | Read-only | Yes | Yes | Yes | Lists root storage and inspects sanitized metadata |
| `files upload` | Writes remote file + local attempt marker/receipt | Yes | Yes | Yes (2026-10-07) | Requires `--sha256` and `--execute`; `starts_print: false`; `remote_byte_hash_verified: false` |
| `files delete` | Deletes one remote root file; preserves local state | Yes | Yes | Yes (2026-11-23, 2026-11-26) | `experimental: true`, `hardware_delete_validated: true` on `20030` / `2.0.2.2` (live wire removal, `files list` absence, and byte-for-byte local state/permission preservation verified) |
| Stored-file download (`files download`) | N/A (not implemented) | No | N/A | No endpoint identified on FW `2.0.2.2` (investigated 2026-11-25) | The 2026-11-25 investigation of stock Kobra X LAN firmware `2.0.2.2` found no HTTP (`:18910`/`:18088`) or MQTT `file/*` download endpoint for stored `.gcode` or timelapse `.mp4` files; see [validation evidence](usage.md#validation-evidence) |
| `print plan` | Read-only | Yes | Yes | Yes | `dry_run: true`, `experimental: true`, `hardware_start_validated` reflects centralized evidence |
| `print start` (initial and `--reprint-from`) | Starts stored file + local attempt marker/receipt | Yes | Yes | Yes (observed cases, 2026-10-07, 2026-11-23, 2026-11-24) | `experimental: true`, `hardware_start_validated: true` only for observed single-filament (`0 -> 1\|2\|4`) and 4-color contiguous 1:1 (`0..3 -> 1..4`) PLA High Speed cases |
| `print watch` | Read-only on printer; writes local observation on active job | Yes | Yes | Yes (2026-11-21, 2026-11-23) | Firmware `2.0.2.2` reports `task_id: "-1"` and empty `last_project`; terminal outcomes remain `unknown` |
| `print pause` / `print resume` / `print cancel` | Single-shot lifecycle control; preserves local receipts/markers | Yes | Yes | Yes (2026-11-23) | `experimental: true`, `hardware_control_validated: true` on `20030` / `2.0.2.2`; `resuming`/`stopping` may exceed the 5 s poll window |
| `jobs list` / `jobs info` | Local read-only | Yes | Yes | Yes (integrated session 2026-11-23) | `scope: "local_state_only"`, `direct_printer_history_available: false`, `terminal_outcomes_verified: false` |
| `completion bash\|zsh\|fish` | Local stdout only | Yes | Yes (native `bash` smoke test; `zsh`/`fish` when installed) | N/A (offline) | Offline generator; never discovers printer names or reads credentials |
